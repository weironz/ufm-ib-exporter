# Rust 重写：架构、参考实现与边界

本仓库维护 exporter 实现；监控部署仓库引用版本和配置。部署前提是 exporter 与 UFM 同机读取回环接口，监控平台消费筛选结果。当前提交是代码交付，不是生产部署。

官方文档建议按单分片耗时调节分片量；这不是建议无限并发。配置 `urls` 时本程序依次读取需要的部分，输入字节数和超时预算按整轮合计，任一部分失败就不发布。原生分片是否支持、应覆盖几个部分，必须先在目标版本验证；本程序不会自动生成或探测路由。

## 数据通路

```text
REST JSON（小且有上限） ─→ 物理口识别 / 节点基线 ─→ REST 缓存
9001 Prometheus 文本 ─→ 指标白名单 / 标签过滤 ─→ 9001 缓存
9002 CableInfo 文本 ─→ 光学白名单 / 标签过滤 ─→ 9002 缓存
                                               ↓
                                   同一个 /metrics，引用共享缓冲
                                               ↓
                                    Prometheus / vmagent
```

三个任务各自循环，“采完＋等待”而非按时无限叠加任务。REST 不等待大源许可；9001/9002 默认共享一个许可。同一来源不重叠，两个大来源默认也不重叠。

客户端使用连接池，支持上游提供的 gzip，默认校验证书，禁止自动跳转。解压后的字节同样受输入上限约束，防止仅依赖压缩 Content-Length。Cloud 使用系统 CA，不关闭验证。

## 流式过滤与内存

扫描器以字节查找换行，完整行尽量借用网络片段；只有跨片段行进入有界暂存区。每次最多处理 64 KiB 后让出执行机会，避免大源长期占据运行线程。

先判断指标名白名单，再解析选中样本的必要标签、数值和显式时间戳。常见标签列表使用栈内小数组；输出字节缓冲直接变成可共享的 `Bytes`。标签集合和指标名分别驻留，用整数对检查重复，避免为每条指标再存一份长身份字符串。

每来源限制原始输入、单行、导出缓存（含元数据和观测时间指标）、业务系列数、标签组合数和指标名数。REST 完整解析 JSON，但其输入有较小上限。大小预算不是精确 RSS 上限：哈希表、分配器容量、HTTP 缓冲及运行库也占内存。

同时存在旧快照、新一轮暂存和正在响应的旧快照时，实际内存高于一份缓存。`max_concurrent_scrapes` 限制响应体共享持有者；慢客户端仍会使已发送的响应数据驻留一段时间。应结合容器内存上限和实测，不能仅把两个 `max_cache_bytes` 相加当作进程峰值。

两个来源同时导出相同业务指标族会使类型/样本语义冲突。本实现保守地拒绝后发布的重叠来源，返回 `source_overlap`，要求使用不重叠白名单。某一来源内部的多个分片可以含同族不同身份；重复样本、删标签造成的碰撞会拒绝整轮。

## 缓存与原生时间

完整处理成功后才切换快照；HTTP 处理器只克隆引用，不读取 UFM、不重新解析大响应。TYPE/HELP 与业务值使用独立共享缓冲，保持类型声明位于样本之前。

原生毫秒时间戳必须有效，旧观测和过远未来观测被排除。默认以正常 scrape 时间输出缓存业务值，同时用 `ufm_telemetry_observed_at_seconds` 明确保留实际观测时刻。缓存过期或最旧接受观测过期，就停止输出整源业务值；这种保守策略可能暂时隐藏部分仍新鲜的数据，但不会继续展示过期值。

此策略让慢刷新的光学指标可在正常 Prometheus lookback 下展示，同时保持可查询的实际年龄；它不提高硬件观测频率。需要原始样本时间语义时可启用 `preserve_timestamps`，并接受慢采集带来的 lookback 空档。原生时间缺失时默认拒绝，显式关闭要求后只能证明最近读取成功，不能证明设备数据新鲜。

超时、错误状态、空数据和资源上限失败不会清除诊断快照，但立即停止业务输出。状态计数保留，设备健康不补零。只改写 HTTP 时间、无限回放旧缓存的做法没有沿用。

## 配置与兼容

YAML 为完整配置，环境变量兼容旧版常见键并覆盖 YAML。9002 的部分配置继承其光学默认值。未知字段、非法正则、嵌入认证信息的 URL、空白名单和无效预算在启动/重载时拒绝；密码从环境注入，日志只记录来源和有限错误分类。

SIGHUP 先完整验证配置，再切换代号、清缓存并通知任务。旧代进行中的结果不能覆盖新配置；无效重载保留原配置。监听、CA 和运行线程/许可数量需重启。

保留既有 `ufm_ib_*` 与原生 telemetry 名称。REST 增加 `ufm_ib_node_links_expected` 以支持配置化告警基线；链路缺口使用非负差额，超出基线的实际在线数仍由 `ufm_ib_links_up` 显示，不能据此补造健康结论。

## 尚需现场验证

- 当前 UFM 版本的计数集、分片、CableInfo 路径和 XDR 标签覆盖；源时间是否持续推进。
- 同机 exporter 资源占用及 UFM 本身序列化成本；Rust 不会消除源端生成大响应的工作。
- 当前固定白名单是否覆盖需要的 FEC/BER 名称；错误计数变化率不能自动当作显式 BER。
- 模块功率/温度的单位与告警阈值、目标完整性、自然周期和现有面板的对应关系。

本地单元、模拟 HTTP、真实 Prometheus、Docker 和合成压测只覆盖软件行为，不替代生产验收。
